# 전통 화질 개선 기법 비교 결과

학습이 필요 없는 전통 기법 8개를 야간 차량 이미지에 적용해 원본과 탐지 정확도·처리 시간·화질 지표를 비교한 결과입니다. 데이터셋, 탐지 모델, 지표는 딥러닝 개선 모델을 비교한 실험과 같아서 두 실험의 숫자를 바로 비교할 수 있습니다. 딥러닝 개선 모델은 다른 팀원이 맡았으므로 이 실험에서는 돌리지 않았습니다.

## 1. 요약

- 원본보다 평균 탐지가 나아진 기법은 CLAHE(+0.0045)와 Gamma(+0.0006) 두 개뿐이고 둘 다 0에 가깝습니다. 새로 넣은 기법 6개(HE, AGCWD, MSRCR, LIME, Dong, BIMEF)는 4개 데이터셋 평균 AP50이 모두 떨어졌습니다.
- 많이 밝히는 기법일수록 탐지가 많이 떨어졌습니다. HE(−0.088), LIME(−0.075), MSRCR(−0.070), Dong(−0.049)은 어두운 영역의 잡음과 JPEG 블록까지 키웠습니다. 화질 지표(NIQE)는 오히려 가장 좋았습니다.
- AGCWD와 BIMEF는 원본과 거의 같았습니다(−0.005, −0.002). BIMEF는 DarkDriving에서 +0.026으로 올랐지만 한 장에 1초가 넘게 걸립니다.
- 선택 규칙(5장)대로 고르면 **빠른 모델은 CLAHE, 확실한 모델은 Gamma**입니다. 딥러닝 비교 때와 같은 결론입니다.
- 파라미터를 바꿔 보니 보정을 약하게 할수록 나았습니다(4장).
  - **Gamma γ1.2(+0.0072):** 4개 데이터셋 모두 F1 점 추정이 양수였고 유의하게 떨어진 곳이 없었습니다. 4개 탐지 설정 모두에서도 원본과 같거나 조금 나았습니다.
  - **CLAHE clip 1.0(+0.0075):** ACDC와 DarkDriving에서 F1이 유의하게 올랐습니다.
  - **최종 추천:** 빠른 모델은 **CLAHE clip 1.0**(개선 약 10~14ms), 확실한 모델은 **Gamma γ1.2**(약 1ms)입니다.
  - **한계:** 그래도 효과의 크기는 AP50 +0.01이 안 됩니다. 결과를 보고 값을 골랐으므로 다른 이미지로 다시 확인해야 합니다(4.5절).

## 2. 실험 설정

### 2.1 비교 조건 (원본 + 전통 기법 8개, `configs/traditional.yaml`)

| 조건 | 방식 | 출처 | 설정 |
|---|---|---|---|
| 원본 | 기준 | - | 개선 없음 |
| Gamma | 고정 감마 곡선 | - | γ = 1.5 |
| CLAHE | 칸별 대비 제한 평활화 (LAB의 L) | Zuiderveld, Graphics Gems IV 1994 | clip 2.0, tile 8×8 |
| HE | 전역 히스토그램 평활화 (LAB의 L) | - | CLAHE 비교용 기준선 |
| AGCWD | 이미지마다 감마 곡선을 자동으로 정함 | Huang et al., IEEE TIP 2013 | α = 0.5 |
| MSRCR | 여러 크기 블러로 조명을 빼는 Retinex | Jobson et al., IEEE TIP 1997 | σ 15·80·250 |
| LIME | 조명 지도 추정 후 나눔 | Guo et al., IEEE TIP 2017 | BM3D 잡음 제거는 뺌 |
| Dong | 반전 → 안개 제거 → 반전 | Dong et al., ICME 2011 | - |
| BIMEF | 노출을 바꾼 사진과 섞음 | Ying et al., arXiv 2017 | - |

Gamma와 CLAHE는 1차 실험과 같은 구현입니다. 나머지 6개는 `src/enhance/traditional.py`에 논문 식대로 새로 구현했습니다. 모두 CPU(NumPy·OpenCV·SciPy)에서 돌아갑니다.

### 2.2 데이터셋·탐지 모델·지표

**데이터셋 (4개, 각 300장, seed 42)**

| 데이터셋 | 사용한 부분 | 평가 클래스 | 정렬된 낮 이미지 |
|---|---|---|---|
| BDD100K | 공식 val 중 야간 3,929장 | 6개 | 없음 |
| ExDark | 전체 4,077장 | 5개 (truck 없음) | 없음 |
| ACDC | night train·val 506장 | 6개 | 없음 |
| DarkDriving | 탐지용 val 2,217장 | car | 있음 |

- 클래스는 person, bicycle, car, motorcycle, bus, truck 6개로 맞췄습니다. rider는 person으로 합쳤습니다.
- 모든 이미지는 긴 변을 1280px 이하로 줄이고 정답 박스도 같은 비율로 줄였습니다.

**탐지 모델 (측정 도구)**

- BDD100K로 학습한 YOLO26s·YOLO26m(Hugging Face `dronefreak/bdd100k-yolo26s`, `-yolo26m`)을 입력 640·960으로 돌렸습니다. 탐지 설정은 4개이고 기준은 yolo26s 640입니다.
- 탐지기는 개선 효과를 재는 도구로만 쓰고 다시 학습하지 않았습니다.

**지표**

- **탐지:** Precision, Recall, F1(신뢰도 0.25 이상, IoU 0.5), AP50, AP50-95(IoU 0.50~0.95), 객체 크기별 AP50(소 < 32², 중, 대 ≥ 96²)
- **화질 (pyiqa):** 정답 기반 PSNR·SSIM·LPIPS(정렬된 낮 이미지가 있는 DarkDriving만), 정답 없는 NIQE·BRISQUE·MUSIQ·CLIP-IQA(모든 데이터셋)
- **처리 시간:** 개선 시간(준비·계산·후처리), 탐지 시간. 조건마다 워밍업 10회 뒤 이미지마다 1회 쟀습니다.
- **선택 규칙:** 빠른 모델은 시간 기준 안에서 평균 ΔAP50이 가장 큰 조건, 확실한 모델은 데이터셋별 ΔAP50 순위의 평균이 가장 작은 조건입니다(5장).

### 3.5 왜 떨어졌나: 잡음 증폭

아래 설명은 `results/20261127-115620_traditional_300/samples/bdd100k/<조건>/`에 저장된 이미지(빨강: 정답, 초록: 탐지)를 조건별로 나란히 놓고 본 것입니다. 데이터셋 이미지는 라이선스 때문에 저장소에 넣지 않았습니다. 같은 비교는 Streamlit 화면이나 `scripts/compare_frame.py`로도 볼 수 있습니다.

- **HE:** 밝기 분포를 억지로 평평하게 펴서 하늘과 노면이 뿌옇게 들뜨고 차의 대비가 오히려 줄었습니다.
- **LIME, MSRCR:** 어두운 영역을 크게 나눠서 밝히는 방식이라 그 영역에 있던 JPEG 블록과 색 잡음도 같은 비율로 커졌습니다. LIME 논문은 이 잡음을 BM3D로 지우지만 이번 구현에서는 그 단계를 뺐습니다. 느린 데다 이번 비교에서는 밝기 보정 효과만 보려고 했습니다.
- **Gamma, CLAHE:** 밝기를 조금만 바꿔서 원래 모습이 거의 그대로 남습니다.

객체 크기별로 보면(4개 데이터셋 평균 AP50), 작은 객체(< 32²)에서는 원본(0.230)보다 CLAHE(0.273), LIME(0.268), Dong(0.262)이 높았습니다. 하지만 HE, LIME, MSRCR, Dong은 중·대 객체에서 크게 떨어졌습니다. 예를 들어 대형 객체 AP50은 원본 0.691, HE 0.574, LIME 0.616이었습니다. 밝히면 멀리 있는 작은 물체는 보이지만 가까운 큰 물체의 윤곽이 잡음에 묻힙니다.

| HE | 10.7 | 14.9 | 20.5 | 31.2 |
| CLAHE (clip 2.0) | 13.5 | 19.7 | 20.3 | 33.8 |

- 모든 기법이 CPU에서 돌아가서 GPU 메모리는 쓰지 않습니다.
- LIME과 BIMEF는 큰 희소 선형계(이미지 픽셀 수만큼의 미지수)를 풀어서 1~2초가 걸립니다. DarkDriving처럼 큰 이미지에서는 LIME이 평균 3.5초였습니다.
- 같은 탐지기, 같은 이미지인데도 원본의 탐지 시간이 실행마다 달랐습니다.
  - 1차 실험 14.9ms, 이번 실행 20.3ms, 파라미터 비교 실행(4장) 12.3ms였습니다.
  - 개선 시간도 같은 방향으로 흔들렸습니다. CLAHE는 이번 실행 13.5ms, 파라미터 비교 실행 10.5ms였습니다.
  - 탐지 코드와 설정은 그대로이니 실행할 때의 PC 상태 차이로 봅니다.
- 그래서 개선+탐지 합계를 33.3ms에 맞추는 규칙은 실행마다 결과가 바뀝니다. 실제로 CLAHE의 합계는 25.9ms → 33.8ms → 22.4ms였고 이번 실행에서만 기준을 넘었습니다(5.1절).

## 5. 진행 중 정한 것

### 5.1 빠른 모델의 시간 기준

`scripts/analyze.py`는 "개선+탐지 합계 ≤ 33.3ms(30fps)" 조건을 그대로 씁니다. 이 규칙으로 고르면 이번 실행의 빠른 모델은 Gamma가 됩니다(CLAHE 33.8ms 탈락). 하지만 이 프로젝트에서는 실시간 처리를 필수 조건에서 뺐습니다. 게다가 3.7절처럼 탐지 시간이 실행마다 5ms씩 흔들려서 문서에서는 아래처럼 판단했습니다.

- **기준:** 탐지 시간은 빼고 **개선 시간만** 봅니다.
  - 기준값은 30fps 한 프레임(33.3ms)에서 탐지 시간(1차 실험 14.9ms)을 뺀 약 18ms입니다.
  - 탐지기는 모든 조건에서 같으니 조건 사이의 차이는 개선 시간에서만 생깁니다.
- **결과:** Gamma(1.0ms), AGCWD(7.4ms), HE(10.7ms), CLAHE(13.5ms)가 기준 안에 듭니다. 이 중 평균 ΔAP50이 가장 큰 **CLAHE가 빠른 모델**입니다.
  - p95(19.7ms)는 기준을 조금 넘습니다. CLAHE는 CPU(OpenCV)에서 돌리므로 GPU 구현으로 바꾸면 줄어들 여지가 있습니다.
- **나머지 기법:**
  - Dong, MSRCR(약 0.2초)은 프레임을 건너뛰는 준실시간용입니다.
  - BIMEF, LIME(1~2초)은 사진 한 장을 다시 보는 오프라인 분석용입니다.
- **코드:** `scripts/analyze.py`의 33.3ms 규칙은 1차 실험 결과와 비교할 수 있도록 바꾸지 않았습니다.
- **파라미터 비교 실행(4장):** 탐지가 빨라서(12ms) 10개 조건이 모두 33.3ms 안에 들었습니다. 개선 시간만으로 판단해도 CLAHE(10.5ms), AGCWD(5.4ms), Gamma(0.8ms) 모두 18ms 안이라 결론이 같습니다.

### 5.2 확실한 모델

확실한 모델은 데이터셋마다 매긴 ΔAP50 순위의 평균이 가장 작은 조건입니다. Gamma(순위 평균 2.25)가 BIMEF(2.75), CLAHE(3.00)보다 앞섰습니다. 다른 탐지 설정에서도 다음처럼 Gamma가 3번, CLAHE가 1번 뽑혔습니다.

### 5.3 느린 기법을 파라미터 비교에서 뺀 이유

HE, MSRCR, LIME, Dong은 4개 탐지 설정 모두에서 평균 ΔAP50이 −0.035 이하였습니다. BIMEF는 원본과 비슷했지만 한 장에 1초가 넘게 걸립니다. 그래서 파라미터 비교(4장)는 빠르고 원본보다 크게 나빠지지 않은 Gamma, CLAHE, AGCWD만 했습니다.

## 6. 한계

- **파라미터 선택:** 4장의 γ1.2와 clip 1.0은 평가에 쓴 이미지로 고른 값입니다. 다른 seed로 뽑은 300장(`configs/traditional_sweep.yaml`에 `seed: 7`처럼 한 줄 추가)으로 다시 확인하는 것이 다음 단계입니다.
- **보정 세기:** ExDark는 약한 보정, DarkDriving은 센 보정에서 좋았습니다. 이미지 밝기에 따라 세기를 바꾸는 방식(예: 평균 밝기로 γ 정하기)을 따로 실험해 볼 수 있습니다.
- **LIME:** BM3D 잡음 제거를 뺀 구현입니다. 잡음 제거를 넣으면 LIME 결과는 나아질 수 있지만 그만큼 더 느려집니다.
- **처리 시간:** Python·CPU 구현 기준입니다. LIME과 BIMEF는 C++나 GPU 구현에서 훨씬 빠를 수 있습니다.
- **탐지기:** BDD100K 학습 탐지기 한 계열만 썼고 평균 AP50 차이 0.005 정도는 데이터셋 하나로 쉽게 뒤집히는 크기입니다. 낮 이미지 위주로 학습한 탐지기(COCO)로는 확인하지 않았습니다.
